# Ford factory ACC

`Use Ford Factory ACC` lets the original Ford camera/radar/ACC system control
gas, brakes, following distance and stop/resume. BlueDragon continues to steer
using the selected Ford controller, including the BluePilot settings.

The option defaults to OFF, preserving the previous openpilot longitudinal
behavior. This is different from disabling Experimental Mode: ordinary
openpilot ACC still plans speed and runs an acceleration feedback controller.

## Select the mode

1. Park, switch the ignition off, and wait for the comma's offroad screen.
2. Open **Settings > BlueDragon > Longitudinal > Use Ford Factory ACC**.
3. Enable the option and reboot the comma before switching the ignition on.
4. Use the Ford controls to set speed and following distance, and to resume
   after a stop when required by the factory ACC.

To return to the previous speed controller, disable this option while parked
and reboot again. There is no live handover between speed controllers.
The setting only affects Ford; it does not alter Pacifica behavior.

The vehicle must have functioning, correctly configured factory ACC. This mode
does not repair or bypass camera/radar calibration faults. The author's test
vehicle is a retrofitted Fusion Hybrid using the Edge MK2 profile; laboratory
tests cannot confirm the behavior of that physical retrofit.

## Control and safety boundaries

- `CarParams.openpilotLongitudinalControl` is false and PCM cruise ownership is
  retained. The Experimental Mode capability is disabled for this mode.
- A separate Ford factory-ACC safety bit (8) is selected at startup, in addition
  to the existing steering bits. It takes precedence over LONG_CONTROL if both
  bits are accidentally supplied.
- The host does not transmit ACCDATA (0x186). Panda rejects host ACCDATA on
  every bus, including inactive payloads and when ALKA or ACC is enabled.
- Original camera ACCDATA is forwarded from bus 2 to bus 0. Original AEB
  ACCDATA_2 (0x187) continues to pass through.
- Automatic resume generated by the openpilot planner is suppressed in the
  controller and rejected by Panda. Physical resume and gap buttons continue
  to pass through normally. Safety disengagement can still cancel factory ACC.
- Original ACC/FCW display signals are preserved. The existing TJA steering
  indication is still updated; model-generated FCW is not added to factory ACC
  indications in this mode.
- Steering message generation and all steering bounds are retained.

## Matched device package

This feature requires both the new signed H7 application and the ARM Python
3.12 settings library registering `dp_ford_stock_lon`. A source-only copy or
changing only `openpilotLongitudinalControl` is not a complete installation:
the old classic-CAN Ford safety mode blocks the original ACCDATA.

`python3 tools/ford_stock_acc/verify_release.py` verifies packaged firmware,
the settings-library checksum/architecture, and matching source hashes. It is
read-only and does not prove the connected Panda has flashed the image.
Normal pandad startup performs the application flash/signature check.

The `ford-stock-acc` device-test branch includes both matched build artifacts.
The prior `bluedragon-dev` and `bluedragon-1.0` versions remain available.
Use a parked SSH branch switch for this test release; the existing development
installer continues to install `bluedragon-dev`.

After installing and rebooting, turn ignition on while parked and run
`python3 tools/ford_stock_acc/check_mode.py`. It should show Ford factory ACC
saved ON, openpilot speed control false, the factory-ACC safety bit selected,
CAN valid, and no RX safety-check fault. The connected Panda must also report
`DEV-1bc2cb72-DEBUG` with signature prefix `62c8cc6e16dad297` matching expected
in the latest startup log. Parameter bits alone do not establish firmware support.

To roll back to dev2.1, turn ignition off, save `dp_ford_stock_lon` false using
the new Params library, switch back to `bluedragon-dev`, and reboot. Normal
pandad startup restores that branch's bundled H7 application. Do not copy the
new interface into the older branch without the matched package.

## Validation

The host tests cover ownership and paired safety flags for all Ford profiles,
both steering controllers, conflicting settings, suppression of ACCDATA and
automatic resume, cancellation, and preservation of factory ACC/FCW display
signals. Steering CAN bytes are compared across the two speed modes for 4,000
controller updates, covering classic CAN/CAN FD and BluePilot on/off.

Native Panda tests cover classic-CAN factory ACC, BluePilot factory ACC, CAN FD
and conflicting flags. The existing Ford and Pacifica/Chrysler suites also run.
The settings library was built and exercised natively on ARM Python 3.12 with
all 169 declared keys, normal storage operations, clear flags and unknown-key
rejection. The combined suites ran 487 tests (443 passed, 44 inherited skips).
Native ARM and H7 builds passed in GitHub Actions run 41206649843; artifact and
source hashes are recorded in `tools/ford_stock_acc/release.json`.
Vehicle behavior still requires hardware validation.
